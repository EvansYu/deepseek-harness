# 知识图谱维护流程

## 概述

每次代码更新、功能新增、删除或迁移，都在同一变更中评估并维护知识图谱。源码和所属 README 是行为依据；wiki 负责跨领域导航、用户功能与证据关系。生成器检查可机械判断的过期数据，维护者负责语义准确性。

## 日常更新

1. 查看当前 diff，对照 [功能总览](features/index.md)、[能力目录](capabilities/index.md)和 [graph.json](data/graph.json) 找到受影响节点。若存在 `.codegraph/`，先用 CodeGraph 定位代码与调用关系，再按需阅读。
2. 先更新所属源码、README 和已有架构文档，再更新受影响的 `features/`、`architecture/` 与 `data/concepts.json`。新增或删除能力时同步入口、关系、证据和验证路径；移除失效链接，不保留已删除功能为当前能力。
3. 在仓库根目录运行生成和检查：

```sh
pnpm run wiki:update
pnpm run wiki:check
```

4. 阅读生成差异，确认描述、依赖类别、实验标识与人工说明一致；按仓库要求运行相关行为检查及文档检查。若源码变更只修复内部实现，也要刷新源码摘要，并在交付说明中明确“已检查 wiki，功能和架构关系无变化”，无需制造无意义的功能文字改动。
5. 将受影响 wiki 文件与实现一起提交。测试结果仅陈述实际运行内容；不能把生成器成功当成业务行为已通过验证。

## 节点与关系

人工节点采用稳定 ID：`project:`、`architecture:`、`feature:`；生成节点采用 `group:` 与包的完整 npm 名称。人工关系保存在 [concepts.json](data/concepts.json)，包含 `from`、`to`、`relation`、`evidence` 和 `status`。证据使用仓库相对路径；节点的 `page` 指向具体知识页。

`offers` 表示产品提供的功能；`implementedBy` 表示功能由哪些领域实现；`explainedBy` 指向架构解释；`contains` 表示目录归属。清单依赖保留原始 `dependencies`、`peerDependencies`、`devDependencies` 和 `optionalDependencies`，不转换为已确认的运行时调用。函数级关系应先由 CodeGraph 和当前源码核实。

`confirmed`、`inferred`、`unknown` 分别表示已核实、推断和未知。新增关系需要核实证据内容，不得只填一个存在但无关的文件。已有生成的工具、配置和服务目录保留事实所有权，wiki 只建立导航。

`capabilities/*.md` 与 `data/graph.json` 由生成器维护，不手工修改。其余页面用中文维护，作为仓库内部知识索引；采用 `index.md` 入口。将来新增 README 或 docs 下文档时，仍遵守仓库双语配对规则。

## 历史刷新

首次建立知识库、版本回顾或需要扩展历史覆盖范围时，在完整克隆中运行：

```sh
pnpm run wiki:history
```

命令读取本地全部引用与 HEAD 的去重提交，生成历史覆盖报告，并在被忽略的 `history/.cache/` 中保存逐提交说明、路径及引用快照。不会自动获取远端，也不会读取凭据。需要远端历史时，先按任务授权获取相关引用，再重新运行。

人工审核 [演进分析](history/index.md)，补充与当前架构有关的历史解释。历史快照不要求随每次文档提交增长，避免记录自身提交造成循环。维护文档使用 PR 编号、标签和当前文件链接；原始提交标识只保留在忽略的审计文件中。

## 检查范围

`wiki:check` 比较当前 packages 与 apps 文件内容摘要、包元数据、测试入口、依赖关系和生成页；检查图节点唯一性、关系端点、证据文件、节点页面和 wiki Markdown 本地文件链接。新增、删除和内容变化都会触发对应生成数据差异。生成器不联网，不要求业务构建或模型密钥。

检查不证明人工文字与源码语义一致，不解析 Markdown 锚点，也不将动态插件装配等同于包依赖。Python、native、部署配置和 docs 的语义变更仍须人工核对架构与功能页。`test:docs` 和 `doc-sync` 纳入 wiki 检查；历史统计只在显式执行 `wiki:history` 时刷新，不依赖 CI 拥有完整 Git 历史。

## 开发备注

知识图谱的更新是代码变更流程的一部分，不是后台自动监控服务。删除一个能力领域后，生成器报告遗留页面；维护者删除旧页并修复人工链接，再重新生成与检查。
